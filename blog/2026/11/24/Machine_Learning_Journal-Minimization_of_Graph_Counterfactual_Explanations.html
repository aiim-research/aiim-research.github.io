Making Explanations Smaller - Minimizing Graph Counterfactual Explanations with Local Bounded Search

November 24, 2026

Story based on “On the Minimization of Graph Counterfactual Explanations: Theory and a Local Bounded Search Algorithm”, available (open access) at Journal of Machine Learning - Springer

In short

  • Problem. Graph counterfactual explainers usually generate a valid counterfactual and then shrink it, but the shrinking (minimization) step had never been formally studied.
  • Theory. The paper defines the GC-min problem and proves it NP-hard.
  • Method. Local Bounded Search (LBS) is a model-agnostic heuristic that refines any valid counterfactual through bounded edge and node-attribute edits.
  • Result. Across nine datasets, LBS reduces the structural edit distance by up to 98% (for example 189.71 to 2.17 edits on Synthie) and outperforms the existing minimizers under the same model-call budget.




Imagine a model that rejects a loan application and, when asked why, answers with a different application: “had you been a completely different person, you would have been approved”. Technically correct, practically useless. A good explanation should tell us the smallest change that would have flipped the outcome.

This is the idea behind counterfactual explanations: given an input and a black-box model, find a new input that is as close as possible to the original but gets a different prediction. The closer it is, the easier it is for a human to read it, check it, and act on it.

When the data are graphs

Many of the most interesting data are not tables but graphs: molecules, brain connectivity networks, protein structures, social networks. A graph counterfactual is a modified graph, with some edges added or removed and, possibly, some node attributes changed, for which the model changes its mind. “Close to the original” then means “few edits”.

In molecular or biomedical settings this matters a lot. A chemist who is told that removing two bonds changes the predicted toxicity of a compound can inspect the claim. If the explanation instead rewrites half the molecule, there is nothing to learn from it.

The step nobody studied

Most modern graph counterfactual explainers follow a generate-and-minimize recipe (Figure 1): first they produce any valid counterfactual, then they try to trim it so that it moves closer to the original graph while still fooling the model.

Generation has received almost all the attention. Minimization has been treated as an afterthought: either a simple random edge-swapping heuristic, or a step so tightly welded to one specific generator that it cannot be reused or improved on its own. There was not even a formal definition of what minimizing a counterfactual means.

That is the gap this paper, by Rodrigo García, Mario Alfonso Prado-Romero, Francesco Gullo and Giovanni Stilo, sets out to fill.

Theory: a hard problem, formally stated

The authors define the GC-min problem: given a black-box model, a graph, and a valid counterfactual of it, modify the counterfactual so that it remains valid and the number of edits with respect to the original graph is as small as possible.

They then prove that GC-min is NP-hard, by a reduction from the classic Feedback Arc Set problem. The result holds regardless of the task or the model, and holds also when restricted to undirected graphs. In plain words: no one should expect an efficient algorithm that always finds the best possible explanation, so good heuristics are the way forward.

Local Bounded Search

The proposed heuristic is Local Bounded Search (LBS). It is model-agnostic, since it only needs to ask the model for predictions, and it works on top of any generator. Starting from a valid counterfactual, it repeatedly tries small moves, always accepting the first one that improves the solution, in a fixed order of priority:

  1. Single-edit removal: drop one edit and check the model still changes its prediction. Every success makes the explanation strictly smaller.
  2. Shrinking-overshooting: when no single edit can be dropped, remove an edit anyway and compensate with a different one, escaping dead ends.
  3. Replacement: swap one edit for another, keeping the size constant but restructuring the solution.
  4. Bounded addition: add an edit only while the explanation stays smaller than the best one found so far.

Two design choices keep it honest. The search never goes beyond the size of the best valid solution found, and the authors prove this bound never excludes an optimal solution. And since the model sees the whole graph, structural edits are tried together with a family of node-attribute adjustments (for example smoothing a node’s features towards its neighbours or diffusing them over the graph), so that edge changes and feature changes can help each other.

Does it work?

The experiments cover nine datasets: synthetic ones (Tree-Cycles, Synthie, COLORS-3), brain networks of children with autism (ASD), molecules (BBBP, BZR, AIDS) and proteins (ENZYMES, PROTEINS). LBS is paired with three generators from different families (DCE, OFS, RSGG) and compared against the existing decoupled minimizer obs, plus two further baselines, one of which (RHC) is a plain hill-climber with the same edit operations and the same budget.

The main results:

  • Much smaller explanations. The structural edit distance (GED) falls by up to 98% with respect to the initial counterfactual. With the DCE generator, the average number of edits on Synthie goes from 189.71 to 2.17, on ENZYMES from 55.24 to 2.60, and on COLORS-3 from 91.22 to 8.97. The baseline obs barely moves: on Synthie it only gets down to 177.51.
  • It is the strategy, not the budget. LBS asks the model more questions than obs, so is the gain just more queries? No. With the same budget of 2,500 model calls on Synthie, LBS reaches a GED of 16.23 while obs stays at 183.36. And obs simply spends the whole budget, while LBS typically converges and stops early, with diminishing returns beyond roughly 10,000 calls.
  • The generator matters less than expected. Once minimization is done properly, the generator mostly provides a valid starting point. A cheap variant introduced in the paper, DCEM, whose generator-side cost is constant (one call per class), reaches minimality comparable to the full DCE.
  • Stable across runs. Over three random seeds, the variation is small compared with the gains.



Ablations: every ingredient counts

The authors switch components off one at a time. Allowing node-attribute changes helps substantially on attributed graphs (on BBBP with the RSGG generator, GED drops from 5.29 to 0.69), at the price of somewhat larger feature changes. Removal moves alone fail on attributed data, while swap and addition moves alone fail badly on attribute-free graphs, so the two families are complementary. Finally, the order matters: deferring removals is catastrophic on attribute-free graphs (GED 81.58 against 3.02 on Tree-Cycles), so trying small removals first is the most robust choice.

Where it does not shine

The paper is candid about the limits. Gains are smaller when the initial counterfactual has little redundancy or when the class depends on a global property of a large, dense graph: on AIDS (tiny molecules) GED goes only from 15.09 to 11.90, and on PROTEINS from 67.45 to 45.86, because many edits are individually necessary. In those cases the search can get stuck in local optima, and the authors point to a learned strategy selector as future work. Other directions are comparison with simulated annealing or tabu search, domain-specific plausibility constraints, and richer edit spaces.

Why this matters

The practical message is a change of perspective for explainability systems: treat minimization as a first-class component. A decoupled minimizer can be plugged on top of any existing counterfactual generator, makes different generators comparable on fair ground, and can turn even a rough, valid counterfactual into a concise explanation a human can actually read.

The experiments run on the open-source GRETEL framework, and the experimental configurations are publicly released.
